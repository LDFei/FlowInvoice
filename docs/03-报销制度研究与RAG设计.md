## 1. 调研结论：真实报销制度的结构

| 维度 | 内容 | 结构化程度 | 落地方式 |
|------|------|-----------|---------|
| 审批链 | 金额阈值 × 职级 → 审批角色链 | **高（数值/枚举）** | YAML 策略引擎（确定性） |
| 差旅标准 | 交通等级、住宿限额、包干金额 | **高（数值）** | YAML（部分）+ 条款文本（语义） |
| 票据规范 | 发票抬头/税务监制章/清单/跨期不可报 | 中（规则化） | RAG 条款检索 |
| 制度纪律 | "未按规定等级乘坐超支自理""宴请须总经理批准" | **低（语义条款）** | RAG（非结构化文本） |
| 通用原则 | 真实性/合规性/及时性（30日）/权责匹配 | 低（原则性） | RAG + 回退原因引用 |

**核心判断：报销决策是"混合决策"** —— 结构化数值走确定性引擎（防幻觉、可审计），
非结构化制度文本走 RAG（按场景检索条款、给依据、可解释），两者互补。

## 2. 制度条款语料（app/policy/clauses/*.md）

依据真实制度改写，按业务拆文档、按 `##` 小节切条款，条款号形如 `差旅费:3.1 城市间交通费标准`：

| 文件 | 主要条款 |
|------|---------|
| `差旅费.md` | 交通等级标准 / 住宿限额 / 市内交通 80 元包干 / 伙食补助 / 报销管理（超支自理）|
| `业务招待费.md` | 事前审批 / 宴请须总经理批准 / 扣伙食补贴 / 报销凭证 / 纪律红线 |
| `票据管理.md` | 发票合法性 / 要素完整 / 跨期与补开不可报 / 遗失与粘贴 |
| `通用报销原则.md` | 四项原则 / 30 日时效 / 先申请后办理再报销 / 预算控制 / 借款 |

结构化数值（住宿上限、审批链阈值）**仍留在 `policy/travel.yaml`**，两套并存、职责分离。

## 3. RAG 架构（app/shared/policies/rag.py + tools/policy_rag_tool.py）

```
制度条款 .md ──切块──▶ PolicyIndex ──检索──▶ 命中条款 {clause_id, source, text, score}
                                                        │
合规节点 check_compliance ──查票据面上下文──▶ query ────┘
        └─▶ state.policy_basis ──▶ 总结节点引用条款号 / 退回原因带依据
```

- **检索后端可插拔**：
  - 默认 `BM25 词法检索`（字符二元组 + IDF，纯标准库、离线、确定性、可复现）
  - 配置 `RAG_BACKEND=vector` 可切换 LangChain text-splitter + Chroma + 嵌入模型（真实向量 RAG）
- **落点**：合规节点产出 `policy_basis`；总结节点引用条款号；回退原因可带依据（可解释性）。

## 4. 面试叙事

1. **为什么不是全 RAG**：金额/审批链是确定性决策，RAG 引入幻觉风险，"钱的事不靠 LLM 猜"。
2. **为什么要有 RAG**：制度条款多且语义化，if-else 维护不现实；退回/拒绝要"有依据"。
3. **混合决策**：确定性引擎兜底 + RAG 给依据 + LLM 生成可解释总结 —— 企业 RAG 落地的典型形态。
4. **可演进**：BM25 离线版先跑通，切真实向量后端只改一个方法，主流程零改动。
